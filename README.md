# DPSA Government Jobs website

The public site is an independent guide to South African public service vacancy circulars and applications. It links to the official DPSA circular page and Z83 form. Any job summaries added through the manager must be checked against the linked department advert.

The static site build adds the site favicon and validates published HTML for titles, descriptions, canonical URLs, page headings, image alt attributes and parseable JSON-LD. The application guide uses `HowTo` structured data; vacancy pages include applicable `JobPosting`, `Article`, breadcrumb and FAQ structured data. These technical checks do not guarantee search rankings or rich-result display.

## Set up the Cloudflare Worker

From the `cloudflare` directory (use `npm.cmd` / `npx.cmd` in Windows PowerShell if script execution blocks the `.ps1` launchers):

1. Install dependencies with `npm.cmd install`.
2. Sign in to Cloudflare with `npx.cmd wrangler login`.
3. Create a KV namespace with `npx.cmd wrangler kv namespace create JOBS`, and add its ID to `cloudflare/wrangler.jsonc`.
4. Create a long, unique admin key and set it as a Worker secret with `npx.cmd wrangler secret put ADMIN_TOKEN`. Enter the same key in the Chrome extension when connecting. Do not put this key in the repository or website code.
5. To enable job alerts, verify a sender domain in Resend, then set `RESEND_API_KEY` and `ALERTS_FROM_EMAIL` as Worker secrets with `npx.cmd wrangler secret put RESEND_API_KEY` and `npx.cmd wrangler secret put ALERTS_FROM_EMAIL`. Use a sender address on the domain verified with Resend. Do not put these values in the repository.
6. To connect the CV matcher and alert registrations to the `DPSAWebsite` Google Sheet tab:
   - Open the spreadsheet, choose **Extensions > Apps Script**, and replace the editor contents with `cloudflare/google-sheets-webhook.gs`.
   - In Apps Script **Project Settings > Script Properties**, add `SHEET_ID` (the spreadsheet ID from its URL), `SHEET_NAME` (`DPSAWebsite`), and a long random `SHEET_WEBHOOK_SECRET`.
   - Choose **Deploy > New deployment > Web app**. Set **Execute as** to your account and **Who has access** to **Anyone**, then deploy and authorize the requested spreadsheet access. The endpoint requires the secret and is called only by the Worker.
   - Set the deployment URL and the exact same secret as Cloudflare Worker secrets: `npx.cmd wrangler secret put SHEETS_WEBHOOK_URL` and `npx.cmd wrangler secret put SHEETS_WEBHOOK_SECRET`.
   - Redeploy the Worker after adding these secrets. If you change the Apps Script deployment, update the URL secret.
7. Deploy with `npm.cmd run deploy`.

The API URL is printed by Wrangler and ends in `/api/jobs`. `GET /api/jobs` returns the published listings. `PUT /api/jobs` replaces them and requires the admin key. The Worker accepts up to 6,000 listings, subject to the 20 MB storage limit. `POST /api/alerts/subscribe` accepts alert preferences from the public site; subscribers must confirm their email before receiving messages. Redeploy the Worker after updating this repository so it accepts imported vacancy details, preserved circular PDF links and job-alert subscriptions.

The Worker config binds the branded `jobs.dpsagovernmentjobs.co.za` custom domain and keeps the existing `workers.dev` endpoint enabled for the website and extension API. Cloudflare must host the `dpsagovernmentjobs.co.za` zone for the custom domain to deploy. Vacancy pages and their sitemap use the branded subdomain.

## Public website

GitHub Pages serves the main homepage and its live vacancy listings. The Pages workflow fetches the public Worker API and renders vacancy cards into the homepage HTML before deployment; the browser then hydrates the search and filters with the latest API data. An hourly workflow refreshes the crawlable snapshot. Set the repository's Pages source to **GitHub Actions** in Settings > Pages to enable this workflow. Each vacancy card links to its crawlable detail page at `https://jobs.dpsagovernmentjobs.co.za/<job-title>-<post-number>-<reference-number>/`. The Cloudflare Worker also serves a live `/sitemap.xml` and `/robots.txt` for vacancy pages. The old `/jobs/` index redirects to the main homepage listings, and old `/jobs/<job-id>/` detail URLs redirect to their new root-level slug. The static root sitemap covers the GitHub Pages guide pages; the Worker sitemap covers its own host. Submit both sitemap URLs in Google Search Console after deployment.

The Worker removes vacancies with an explicit past closing date from public API results and the live sitemap. A closed detail URL returns HTTP 410 with `noindex`. When a department is unavailable, the site labels it as unverified rather than claiming the South African Public Service is the employer. The importer uses the same neutral placeholder so missing department data is easy to review in the extension.

Vacancy detail pages include unique titles, descriptions, canonical URLs, full advert details, and links to the official source. `JobPosting` JSON-LD is emitted when a real hiring organization, publication date, complete description, physical job location, and official source are available. Each detail page also renders vacancy-specific questions about pay, experience, duties, and qualifications, with matching `FAQPage` JSON-LD. Pay estimates use advertised annual/monthly pay when available, otherwise the supplied salary-level guide as a clearly labeled reference, and the SARS 2027 individual tax rates for an under-65 taxpayer with the primary rebate. They exclude UIF, pension/GEPF contributions, medical aid credits, allowances, and other deductions; they are illustrative rather than take-home-pay guarantees. Update the tax brackets and rebate in `salary-scales.js` after each applicable budget change. An expiry date is included when the advert provides one; if it is missing, it is omitted rather than invented. Verified corrections cover legacy Circular 41 records, while future imports use department and centre headings in the source circular. The public homepage points vacancy links at the branded Worker custom domain; the `workers.dev` hostname remains available for the API.

The static fallback `jobs.json` starts empty. The Pages workflow installs the extension's locked dependencies to bundle the optional browser-side CV parsers; PDF and DOCX parsing assets load only after a visitor chooses a file.

The homepage CV matcher accepts PDF, DOCX and plain-text CVs up to 10 MB. PDF and DOCX text extraction is loaded only when a visitor selects a file; parsing and matching happen in the browser. To record a match, the visitor must explicitly consent to sending their name, email, province/department preferences and full extracted CV text through the Worker to the configured `DPSAWebsite` Google Sheet tab. The original file is not sent. CV records remain in the sheet until manually deleted; unsubscribing from email alerts does not delete them. The Worker does not persist CV text in KV. Scanned PDFs that need OCR are not supported. Matching ranks current vacancies by overlapping keywords in the CV and the vacancy title, requirements, skills and duties. The overlap score is not a probability of being hired and cannot verify eligibility; applicants must check the official advert. The separate alert form records name, email and province/department preferences in the same sheet after explicit consent, and sends alerts only after double opt-in. Resend delivers the confirmation and alert emails. Confirmation links expire after 24 hours; unsubscribe stops emails and updates the sheet status to `unsubscribed` without deleting the row. Alerts are sent when new job IDs are published.

AdSense's asynchronous loader is installed once in the public static pages and vacancy-page template. Vacancy pages preconnect to Google's ad servers and request the configured 300x600 display unit directly above Requirements without lazy loading. Ad delivery still depends on Google's ad fill, account and traffic eligibility, and browser settings, so no page script can guarantee that an ad will appear. The root site and Worker subdomain both serve the matching `ads.txt` authorization. Auto ads and site approval remain managed in AdSense.

The DPSA circular and application pages summarize public instructions in original wording and link readers to the official DPSA source. Requirements, duties, and notes use semantic bullet lists on vacancy pages, and the Chrome extension formats those fields consistently for imported posts. Vacancy cards use normal-capitalization titles linking to vacancy pages, department and location metadata, an appointment-type pill, an expiry countdown when a closing date is known, a linked job level when the advert provides one, and an Apply button linking to application instructions. Vacancy detail pages include up to three similar current vacancies, ranked using title, department, and province. Homepage and circular archive listings order known circulars from earliest to latest. Salary-level links open the matching section of the salary guide. Salary text is limited to the pay range and level, not following candidate conditions. Imported circular page numbers are retained with each post. Visual line wraps are joined so sentences are not split, category labels stay with their first point, and detected PDF hyperlinks remain clickable. Confirm current publication dates, vacancy requirements and closing dates on the original department advert.

## Automatic DPSA circular publishing

The `Monitor and publish DPSA circulars` workflow checks the five latest official circular pages every five minutes on Fridays from 09:00 to 12:00 South African time, but publishes only while **Auto publish** is enabled in the Chrome extension. It reuses the extension PDF parser, considers only circulars newer than the latest issue already published in the Worker, and stops instead of publishing when the PDF title does not match the archive or fewer than 75% of detected post sections parse. After a successful publication it records the circular and publication timestamp in Worker history and dispatches the Pages workflow so new listings appear in the homepage snapshot without waiting for the hourly refresh.

Before enabling the workflow on the default branch:

1. Deploy the updated Worker with `npm.cmd run deploy` from `cloudflare`. Its existing `ADMIN_TOKEN`, `RESEND_API_KEY`, and `ALERTS_FROM_EMAIL` Worker secrets must be configured.
2. In GitHub repository **Settings > Secrets and variables > Actions**, add `WORKER_ADMIN_TOKEN` with the same value as the Worker `ADMIN_TOKEN`, `AUTOMATION_ALERT_EMAIL` with the primary notification recipient, and `AUTOMATION_ALERT_EMAIL_ADDITIONAL` with the additional recipient. Never put these values in workflow files or chat.
3. Ensure GitHub Actions is enabled. The workflow can also be started manually with **Actions > Monitor and publish DPSA circulars > Run workflow**.

After deploying the Worker and reloading the extension, connect to the Worker and turn on **Auto publish** in the extension. The setting is off by default and stored in Worker KV; opening the extension shows the current setting and recent automatically published circulars with South African timestamps. The workflow sends a success email after each new circular is published, including the total number of posts and Permanent, Contract, Sessional and Internship counts; failure notices are sent when automation fails. Emails use the Worker’s configured Resend account and go to `AUTOMATION_ALERT_EMAIL`. Parsed vacancy details are normalized to the same field limits as manual extension publishing.

## Search visibility and legacy pages

The site publishes `sitemap.xml` and `robots.txt`; after deployment, submit the sitemap in Google Search Console and inspect indexing there. Unknown main-site URLs use the GitHub Pages `404.html` fallback to send visitors to the homepage. GitHub Pages still returns an HTTP 404 for that initial request; the fallback performs a browser redirect. Recognized legacy vacancy and circular URLs are instead sent to the relevant circular section, whose past-issue list links to the official DPSA publication page. The original closed advert text is not recreated without a verified source. On the Worker host, legacy circular slugs go to the corresponding circular section; other unknown vacancy-page routes, admin paths, and RSS/Atom feed paths go to the main homepage, while sitemap, robots, ads and API responses stay functional. Feed-style query URLs (such as `?feed=rss2` and `?format=feed&type=rss`) are redirected as well.

Province guide pages are generated only for provinces with current listings, use normalized province names and link to current job details. The Gauteng guide explicitly distinguishes DPSA circular posts from a complete Gauteng Provincial Government or municipal vacancy feed.

## Use the custom domain

The repository includes a `CNAME` file for `dpsagovernmentjobs.co.za`. In Cloudflare DNS, point the apex to GitHub Pages using `A` records for `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, and `185.199.111.153`; point `www` to `masasecomm.github.io` with a `CNAME` record. Remove the existing Vercel `CNAME` records for `@` and `www` when making the switch. Keep unrelated TXT records. Use DNS-only proxy status while GitHub provisions HTTPS, then enable Cloudflare proxying only if needed. DNS and certificate changes may take time to propagate.

## Load the Chrome extension

1. Open `chrome://extensions` in Google Chrome and turn on **Developer mode**.
2. Select **Load unpacked** and choose this repository's `extension` folder.
3. Click the DPSA Government Jobs Manager extension icon to open the full-page admin dashboard.
4. Enter the Worker API URL and admin key, then select **Connect and save**. Approve Chrome's prompt to access the Worker.
5. To enable automatic Friday publishing, turn on **Auto publish**. The extension shows recent circulars it published and the time of each publication. This control requires the updated Worker to be deployed and the updated extension to be reloaded.
6. Add, edit, or delete listings. Jobs from any location can appear on the public homepage. Use the published-list **Sort** menu to order posts by post number, recently added order, circular publication date (newest first), or title A–Z / Z–A.
7. To import DPSA vacancies, first run `npm.cmd install` and `npm.cmd run build` inside `extension`. Reload the unpacked extension, then choose local PDFs or use **Find DPSA circulars** to see the five newest circulars and their full PDFs. Approve access to the official DPSA website when Chrome asks. Requirements, duties, and notes are sentence-bulleted consistently for all imported posts. Review or edit extracted vacancies before publishing selected jobs. Scanned PDFs without selectable text cannot be imported automatically. **Download Excel** exports the current review; **Clear import** only clears the review and does not remove published jobs.

The extension remembers the Worker URL and admin key in Chrome's local extension storage on this browser profile. These credentials are not synced by the extension or sent to the website, but they are not separately encrypted by the extension; anyone with access to this Chrome profile or device may be able to access them. Use **Forget saved credentials** to remove them from this browser. The extension asks for site access only to the Worker origin you enter and the DPSA website when importing circulars.
